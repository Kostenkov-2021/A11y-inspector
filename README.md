# A11y-inspector


# Accessibility Inspector - Расширение для проверки доступности веб-сайтов

![Version](https://img.shields.io/badge/version-1.1.0-blue.svg)
![Chromium](https://img.shields.io/badge/browser-Chromium-brightgreen.svg)
![License](https://img.shields.io/badge/license-MIT-green.svg)

Расширение для браузеров на движке Chromium, которое проверяет веб-сайты на соответствие критериям доступности (WCAG и ГОСТ Р 52872-2019) и предоставляет детальные отчёты в различных форматах.

## Возможности

- ** Комплексная проверка доступности** по стандартам WCAG
- ** Проверка контрастности** с реальными расчётами по алгоритму WCAG
- ** Мультиформатные отчёты** (JSON, HTML и обычный текст)
- ** Markdown-отчёты** для быстрой публикации результатов проверки
- ** Проверка изображений** на наличие альтернативных текстов
- ** Проверка клавиатурной навигации**
- ** Анализ семантической разметки**
- ** Проверка ARIA-атрибутов**
- ** Проверка языка страницы и отдельных фрагментов текста**
- ** Обучающие ссылки Doka** в карточках проблем и экспортируемых отчётах
- ** Скачивание отчётов** для дальнейшего анализа

## Поддерживаемые проверки

### Контрастность текста
- Расчёт коэффициента контрастности по алгоритму WCAG
- Проверка соответствия уровням AA (4.5:1) и AAA (7:1)
- Учёт размера и жирности шрифта
- Рекурсивный анализ фоновых цветов
- Композиция простых полупрозрачных цветов текста и фоновых слоёв
- Для градиентов, изображений, фильтров и неподдерживаемых цветов — невыполненное измерение в сведениях об охвате, а не нарушение с ненадёжным числовым выводом

### Контрастность нетекстовой информации
- Проверка границ интерактивных элементов
- Проверка индикаторов фокуса
- Проверка SVG-графики и элементов с ролью `img`

### Изображения
- Отсутствие атрибута `alt`
- Декоративные изображения с пустым `alt` не считаются ошибкой сами по себе
- Доступные имена SVG, объектов и графических кнопок

### Язык контента
- Наличие атрибута `lang` у элемента `html`
- Проверка допустимых значений `lang` у страницы и отдельных элементов
- Поиск фрагментов текста на другом языке без собственного `lang`
- Локальное определение языка без отправки текста во внешние сервисы

### Семантическая разметка
- Наличие заголовков (`h1-h6`)
- Использование семантических элементов вместо `div`
- Корректная структура заголовков
- Наличие информативного заголовка страницы (`title`)

### ARIA-атрибуты
- Проверка корректности использования `aria-label`
- Валидация ARIA-ролей и свойств
- Проверка обязательных ARIA-атрибутов, контекста ролей и доступных имён
- Проверка ссылок `aria-labelledby`, `aria-describedby`, `aria-controls` и других IDREF-атрибутов

### Клавиатурная навигация
- Проверка атрибутов `tabindex`
- Обнаружение потенциальных проблем с фокусом
- Проверка порядка фокуса
- Обнаружение потенциальных клавиатурных ловушек
- Поиск фокусируемых элементов внутри областей с `aria-hidden`

### Размер целей
- Проверка минимального размера целей по WCAG 2.2, критерий 2.5.8
- Учитываются расстояния между целями и исключения, поддерживаемые axe-core
- Неоднозначные результаты отмечаются как требующие ручной проверки

### Сценарные проверки
- Реальный обход клавиатурой через `Tab` и `Shift+Tab`: видимость индикатора, перекрытие фокуса и повторение последовательности
- Проверка адаптации текста при ширине 320 CSS px или высоте 256 CSS px для вертикального письма (1.4.10)
- Поиск нового обрезания текста при увеличении вычисленных размеров шрифта до 200% (1.4.4)
- Проверка возможного полного перекрытия элемента с фокусом (2.4.11, только WCAG 2.2)
- Замечания требуют ручной проверки; геометрические признаки сами по себе не доказывают нарушение

### Навигация
- Проверка ссылок для пропуска навигации
- Проверка `aria-current` у активных пунктов навигации и ссылок текущей страницы
- Проверка случаев, когда для текущей ссылки используется `aria-selected` вместо `aria-current`

### Формы и подсказки
- Проверка связанных подписей и инструкций
- Проверка `autocomplete` для полей с данными пользователя
- Проверка сообщений об ошибках, `aria-invalid`, `aria-describedby` и `aria-errormessage`

### Динамический и всплывающий контент
- Проверка live regions и статусных сообщений
- Проверка всплывающих подсказок и контента, который появляется при наведении или фокусе
- Проверка устойчивости интерфейса к увеличенным интервалам текста
- В сценарном режиме — реальные движения указателя и Escape для связанных `role="tooltip"`, сравнение наведения и фокуса
- Наблюдение изменений статусных сообщений; оно не заменяет проверку объявлений скринридером

### Медиаконтент и пользовательские процессы
- Поиск видео без встроенных дорожек субтитров и плееров без нативных controls; в сценарном режиме — наблюдение медиасобытий и продвижения воспроизведения
- Проверка отмены пробного события вставки в явно заданном сценарии аутентификации
- Явно заданные сценарии ввода, нажатий, указательного перетаскивания и переходов между шагами одного origin
- Постусловия действий: текст, значение, checked, видимость, доступность и фокус; операции нативных checkbox и select с подтверждением состояния
- Поиск обязательного повторного запроса данных с нормализацией `autocomplete`, различением секций и назначений адреса/контакта
- Все эти наблюдения требуют проверки применимости; наличие альтернатив и качество медиаконтента не доказываются автоматически

### Стандартные проверки
Часть проверок выполняется локальным движком axe-core 4.14.0 с русской локализацией. В расширение включены все необходимые файлы; текст страницы не отправляется во внешние сервисы.

Стандартный набор включает 41 правило для имён элементов, ARIA, языка, таблиц и размера целей. Он проверяет основной документ, включая элементы ниже видимой области и открытые Shadow DOM. Содержимое iframe и закрытые Shadow DOM в этом режиме не проверяются; проверяются названия самих iframe. Для остальных проверок сохраняются ограничения существующего сканера.

В JSON-отчёт добавлены `coverage` со списками выполненных правил и `outcome` у результатов стандартного набора: `violation` — обнаруженное нарушение, `incomplete` — требуется ручная проверка. В человекочитаемых отчётах ручная проверка явно обозначена в сообщении и подробностях. Отсутствие замечаний не подтверждает полное соответствие WCAG или ГОСТ. Критерий 2.5.8 относится к WCAG 2.2 и не помечается как требование ГОСТ 2019.

## Установка

### Установка из исходного кода

1. **Клонируйте репозиторий**
   ```bash
   git clone https://github.com/Kostenkov-2021/A11y-inspector.git
   cd A11y-inspector
   ```

2. **Установите расширение в браузере**
   - Откройте браузер Chrome/Edge/Brave
   - Перейдите на страницу `chrome://extensions/`
   - Включите "Режим разработчика" (переключатель в правом верхнем углу)
   - Нажмите "Загрузить распакованное расширение"
   - Выберите папку с расширением

### Установка из файла

1. Скачайте последнюю версию расширения из [Releases](https://github.com/Kostenkov-2021/A11y-inspector/releases)
2. Распакуйте архив в выбранную папку
3. Следуйте шагам 2-5 из инструкции выше

## Использование

### Базовое использование

1. **Откройте расширение**
   - Нажмите на иконку расширения в панели инструментов браузера

2. **Введите URL для проверки**
   - Вставьте URL сайта в поле ввода
   - Или используйте текущую вкладку (URL подставляется автоматически)

3. **Выберите формат отчёта**
   - JSON - для программной обработки
   - HTML - для визуального просмотра
   - Обычный текст - для быстрого импорта
   - Markdown - для документации, задач и отчётов в репозитории


4. **Запустите проверку**
   - Нажмите кнопку "Проверить"
   - Дождитесь завершения анализа

5. **Просмотрите и скачайте отчёт**
   - Изучите результаты в интерфейсе расширения
   - Скачайте отчёт в выбранном формате

### Расширенное использование

#### Профили и результаты
Выберите WCAG 2.2, ГОСТ Р 52872-2019 или совместный профиль. Для WCAG 2.2 синтаксические замечания `4.1.1` не включаются как требования этого стандарта; новые критерии WCAG 2.2 не выдаются за требования ГОСТ 2019. Ошибки семантических связей отдельно сопоставляются с применимыми критериями. Можно включить доступные проверки AAA, в том числе усиленный текстовый контраст; это не полный аудит уровня AAA.

Все замечания имеют `outcome`: `violation` для технически подтверждённого нарушения или `incomplete` для ручной проверки. Старые эвристики консервативно относятся к `incomplete`. В `coverage.results` стандартные тесты используют также `passed`, `inapplicable` и `not-tested`; результаты вне профиля явно отделены. Пройденное правило не означает соответствие всему критерию.

В набор включаются только автоматические проверки и автоматически полученные признаки, требующие ручного подтверждения. Поле `assessment` различает `automatic` и `assisted`; ошибки выполнения отмечаются отдельно как `diagnostic`. Неподдерживаемые измерения находятся в `coverage.notTested`, а не в списке нарушений. Напоминания только по наличию `draggable`, `autocomplete="off"` и предполагаемого движения не создаются. Синтетическая отмена Tab не используется для вывода о клавиатурной ловушке.

Количественные ограничения записываются в `coverage.limits` и в сведениях об отдельных сценариях: размер выборки, лимит, число отобранных кандидатов и признак усечения. Достижение лимита до завершения прохода явно делает охват неполным. Эти сведения показываются и в отчётах без замечаний. Ограничение старых эвристик областью viewport сохраняется.

#### Пользовательские сценарии
В разделе «Пользовательский сценарий» можно указать JSON и отдельно разрешить его действия. Пустое поле не запускает ввод, клики, перетаскивание или отправку форм. Сценарий ограничен одним origin, 30 шагами и бюджетом времени 30 секунд, проверяемым между шагами и перед Input. Разрешённые действия могут изменить данные сайта; закрытие отдельной вкладки не отменяет серверные изменения.

Используйте только тестовые данные и разрешённые тестовые сайты. Реальных учётных данных для проверки не требуется. Проба вставки синтетическая и не читает системный буфер обмена; она не доказывает поведение настоящей вставки. Формат и пример приведены в [описании сценариев](docs/SCENARIOS.md).

check и fill требуют однозначного селектора; fill работает только с текстовыми полями и подтверждает значение. Действие привязывается к конкретному DOM-узлу: исчезновение, замена и изменение вариантов select не дают ложный completed. Можно задать timeoutMs до 5000 мс. Для drag доступны mode native и явно разрешённая управляемая прокрутка scroll true; это не универсальная краевая автопрокрутка приложения.

К действию можно добавить `expect`, например `{ "action": "click", "selector": "#next", "expect": { "selector": "#result", "text": "Готово", "visible": true } }`. Без достижения постусловия шаг не завершается. Есть checkbox, radio, одиночный select, multiple с массивом values, ARIA-listbox с массивом селекторов options и действие aria для логического состояния checked/selected/expanded/pressed. Состояния подтверждаются после реальных событий; это не проверка всех способов управления компонентом. Отчёт различает постусловие, состояние поля, наблюдение и только отправку действия.

Явные переходы в селекторе: `#host >>> #field` для открытого Shadow DOM и `#frame >>frame>> #field` для iframe того же origin. Чужие, изолированные и преобразованные фреймы отклоняются. Действия media и observe собирают сведения о пользовательском плеере и поздних обновлениях до 5000 мс. Повторный ввод без autocomplete сопоставляется только по точным нормализованным подписям с разделением форм и контекстов; смысл подтверждается вручную.

Для drag добавлено autoScroll true: краевой цикл во вложенных областях и документе, по обеим осям и в RTL. Расширение может помогать небольшими резервными прокрутками; это явно отмечается в отчёте, а не выдаётся за собственную автопрокрутку сайта. Есть лимиты времени и итераций.

Действие pattern охватывает каталог из 30 APG-паттернов через явно заданные клавиши и проверяемые состояния, включая expect.attributes. Распознавание роли не считается полным аудитом компонента. Действие web-audio наблюдает контексты, граф и часы через debugger, не записывая и не запуская звук; продвижение часов не доказывает слышимость. Примеры и ограничения приведены в [сценариях](docs/SCENARIOS.md).

Сценарии сохраняют ограниченное наблюдение событий play/playing/pause/ended, громкости и ожидания данных. Для потенциально звукового интервала учитываются продвижение currentTime, muted и громкость, а не длина файла. Фактический звук, автоматический запуск и наличие подходящего механизма остановки подтверждаются вручную; события до начала наблюдения не восстанавливаются.

#### Сценарная проверка фокуса и адаптации
Перед запуском включите флажок «Сценарная проверка фокуса и адаптации». По умолчанию этот режим выключен. Он работает в отдельной вкладке проверки и временно меняет viewport, размеры шрифта и клавиатурный фокус. После проверки расширение пытается восстановить исходные стили, размер области просмотра, фокус и прокрутку, в том числе при ошибке.

Для режима требуется разрешение `debugger`. Chromium не позволяет запрашивать его как необязательное разрешение, поэтому оно объявлено в манифесте, но подключение отладчика выполняется только при включённом флажке или разрешённом JSON-сценарии. После обновления расширения браузер может запросить подтверждение нового разрешения. Если отладчик недоступен, отчёт явно отмечает незавершённую проверку.

Проверка сравнивает адаптацию с исходной областью 1280 × 800 CSS px, затем увеличивает текст при том же размере области. Удвоение вычисленных размеров шрифта не заменяет проверку всех способов браузерного масштабирования. Геометрический анализ ищет длинные строки и новое обрезание текстовых узлов, но не проверяет всю функциональность элементов управления и все виды потери содержимого.

Охват ограничен 2500 элементами, 40 замечаниями на геометрический этап и 60 нажатиями в каждом направлении. При клавиатурном обходе контролируется общий бюджет времени 25 секунд. Проверяются основной документ и открытые Shadow DOM; содержимое iframe и закрытых Shadow DOM не проверяется. `Enter` и `Space` не нажимаются, поэтому состояния, требующие активации элемента, могут остаться непроверенными.

JSON сохраняет сведения в `coverage.scenarios`. HTML, Markdown и текстовые отчёты показывают завершённые этапы, число клавиатурных шагов и ограничения даже при отсутствии замечаний. Достижение лимитов, переход в iframe или прерывание проверки обозначается как неполный охват. Отсутствие замечаний не подтверждает соответствие WCAG или ГОСТ.

#### Проверка конкретных элементов
Расширение автоматически проверяет все элементы страницы, но вы можете проверять на конкретных проблемах:

- **Контрастность**: Отчёт включает точные значения коэффициентов и требования
- **Нетекстовая контрастность**: Отчёт показывает элементы управления, фокус и графику с недостаточным контрастом
- **Изображения**: Список всех изображений без альтернативных текстов
- **Навигация**: Проблемы с клавиатурным доступом
- **Активные пункты навигации**: Ссылки текущей страницы без `aria-current`
- **Формы**: Поля без подсказок, связанных ошибок или корректного `autocomplete`
- **Язык**: Фрагменты текста, для которых нужен отдельный атрибут `lang`

#### Интерпретация результатов

**Уровни серьёзности:**
- **Ошибка** - Критические проблемы, нарушающие доступность
- **Предупреждение** - Потенциальные проблемы и рекомендации

**Категории проверок:**
- `contrast` - Проблемы с контрастностью
- `non-text-contrast` - Проблемы с контрастностью нетекстовой информации
- `images` - Проблемы с изображениями
- `language` - Язык страницы
- `language-parts` - Язык отдельных частей контента
- `headings` - Структура заголовков
- `aria` - ARIA-атрибуты
- `keyboard` - Клавиатурная навигация
- `keyboard-traps` - Потенциальные клавиатурные ловушки
- `focus-order` - Порядок фокуса
- `forms` - Формы и подписи полей
- `form-assistance` - Подсказки и обработка ошибок в формах
- `semantics` - Семантическая разметка
- `page-title` - Заголовок страницы
- `text-spacing` - Устойчивость к изменению интервалов текста
- `hover-focus-content` - Контент при наведении и фокусе
- `label-in-name` - Соответствие видимой метки доступному имени
- `status-messages` - Статусные сообщения и live regions
- `syntax` - Синтаксис, дублирующиеся `id` и битые ссылки на элементы

### JSON
```json

  "timestamp": "2024-01-15T10:30:00.000Z",
  "issues": [
    {
      "type": "error",
```

## Разработка

### Зависимости и проверки
- Для разработки и тестов используются Node.js 20+ и зависимости из `package.json`
- Установите зависимости командой `pnpm install --frozen-lockfile`
- После обновления axe-core выполните `pnpm run vendor`, чтобы обновить локальные файлы и лицензию в `accessibility-inspector/vendor/`
- Выполните `pnpm test` для регрессионных проверок
- Выполните `pnpm check` для синтаксиса, JSON, UTF-8, ресурсов манифеста и отслеживаемых PEM; `pnpm vendor:check` проверяет воспроизводимость локальных файлов без перезаписи
- В GitHub Actions подготовлены Source checks и Chromium scenarios; `pnpm test:ci` запускает тот же набор с двумя тестовыми файлами одновременно. Настройки обязательных проверок и дополнительные анализаторы рассмотрены в [проверках GitHub](docs/GITHUB-CHECKS.md)
- Браузерные тесты используют headless Edge в Windows; другой канал можно указать через `PLAYWRIGHT_CHANNEL`. На других системах требуется Chromium, установленный командой `pnpm exec playwright install chromium`
- Сквозной тест загруженного расширения использует отдельный временный профиль; его канал задаётся через `EXTENSION_TEST_CHANNEL`
- Для обычной установки расширения Node.js и установка зависимостей не нужны

### Требования
- Браузер на движке Chromium 118+; для других Chromium-браузеров требуется совместимость используемых API расширений
- Базовые знания JavaScript и HTML/CSS

### Архитектура расширения

**Content Script** (`content-script.js`)
- Выполняется в контексте проверяемой страницы
- Собирает данные о доступности элементов
- Реализует алгоритмы проверки контрастности
- Проверяет расширенный набор критериев WCAG и ГОСТ Р 52872-2019

**Background Script** (`background.js`)
- Управляет процессами проверки
- Координирует взаимодействие между компонентами

**Popup Interface** (`popup/`)
- Пользовательский интерфейс расширения
- Отображение результатов и управление настройками

**Report Generator** (`utils/report-generator.js`)
- Генерация отчётов в различных форматах
- Форматирование и экспорт данных
- Добавление справочных ссылок к найденным проблемам

**Doka Links** (`utils/doka-links.js`)
- Подбирает материалы Doka по категории и деталям проблемы
- Используется в popup, предпросмотре и экспортируемых отчётах

**Language Detector** (`utils/language-detector.js`)
- Определяет язык текстовых фрагментов локально в браузере
- Помогает находить части контента без корректного `lang`

## Тестирование

### Ручное тестирование
Для проверки функциональности используйте следующие тестовые сценарии:

1. **Проверка контрастности**
   - Сайты с низкоконтрастным текстом
   - Элементы с различными размерами шрифтов

2. **Проверка изображений**
   - Страницы с изображениями без `alt` атрибутов
   - Декоративные изображения с пустыми `alt`

3. **Проверка семантики**
   - Страницы без заголовков
   - Использование несемантических элементов для интерактивных компонентов

4. **Проверка форм**
   - Обязательные поля без явной инструкции
   - Ошибки формы без связи с конкретным полем
   - Поля имени, email, телефона и адреса без подходящего `autocomplete`

5. **Проверка языка**
   - Страницы без `lang`
   - Смешанный русский и английский текст без `lang` на отдельных фрагментах
