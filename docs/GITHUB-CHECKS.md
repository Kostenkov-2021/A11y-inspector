# Проверки GitHub

## Что подготовлено

Workflow `.github/workflows/ci.yml` запускается при push, pull_request и вручную. Используются Node.js 24, pnpm 10.20.0 и зафиксированные зависимости из pnpm-lock.yaml. Секреты не передаются, GITHUB_TOKEN имеет только contents:read, credentials checkout не сохраняются. Внешние actions закреплены полными SHA; их соответствие указанным major-тегам проверено через официальные Git-репозитории.

| Проверка | Содержание |
| --- | --- |
| Source checks | Синтаксис JavaScript через node --check, JSON, строгий UTF-8 исходников/документации/workflow, существование ресурсов Manifest V3 и отсутствие отслеживаемых PEM-файлов |
| Vendor | pnpm vendor:check сравнивает axe-core, лицензию и подготовленную русскую локализацию с зависимостью из lockfile; проверка ничего не перезаписывает |
| Chromium scenarios | Полный набор node:test, включая распакованное расширение с настоящим debugger, в Chromium Playwright на Ubuntu 24.04 |

Установка выполняется с --frozen-lockfile и --ignore-scripts. Браузер и системные зависимости устанавливаются явно через `pnpm exec playwright install --with-deps chromium`. Для полного Chromium указан канал chromium, в том числе у расширения; один headless-shell для этой задачи не подходит. Параллелизм тестовых файлов ограничен двумя через pnpm test:ci.

Проверка манифеста не является полной реализацией схемы Chrome или анализатором разрешений. Строгий UTF-8 не проверяет смысл русского текста и не заменяет языковые регрессии. Синтаксис YAML и выражений Actions не анализируется собственным JavaScript-скриптом; workflow ещё должен пройти запуск GitHub.

Добавлен `.github/dependabot.yml`: ежемесячные обновления npm-зависимостей (с pnpm-lock.yaml) и GitHub Actions, до пяти открытых PR для каждой группы. Обновление axe-core намеренно требует подготовки vendor-файлов командой pnpm vendor и прохождения тестов; CI не подменяет их автоматически. Dependabot не создаёт обновления локально: конфигурация должна попасть на ветку по умолчанию и быть доступна GitHub.

PEM и CRX исключены из новых добавлений через .gitignore. Имеющиеся локальные ключ и пакет не удалялись. Это не проверка истории Git и не гарантия отсутствия секретов другого формата. Для vendor-файлов закреплён LF, чтобы проверка воспроизводимости не зависела от autocrlf в Windows.

## Что стоит включить следующим

1. **Обязательные проверки в ruleset.** После первого успешного прогона сделать Source checks и Chromium scenarios обязательными для слияния. Настройки GitHub не менялись: одна конфигурация workflow сама по себе не запрещает merge.
2. **CodeQL для JavaScript.** Включить доступный репозиторию code scanning. Это дополнение к браузерным тестам, а не доказательство безопасности отладочного транспорта.
3. **Secret scanning и push protection.** Проверить доступность в настройках репозитория; при необходимости добавить отдельный сканер истории Git. Особенно важно не публиковать ключ подписи расширения.
4. **Dependency review.** Проверять новые зависимости в PR, если эта возможность доступна репозиторию. Наличие Dependabot не равно анализу каждого изменения зависимостей.
5. **actionlint.** Добавить отдельную проверку YAML и выражений workflow с закреплённой версией анализатора. Сейчас собственный checker проверяет для YAML только кодировку.
6. **Дополнительная браузерная среда.** После стабильного Chromium-прогона рассмотреть Windows/Edge. Не делать матрицу обязательной до проверки надёжной загрузки распакованного расширения на выбранном канале.

Эти серверные настройки и дополнительные анализаторы здесь только рассмотрены, но не включены. Обязательные проверки следует привязать к фактически появившимся именам checks после публикации workflow.

## Локальная проверка

```bash
pnpm install --frozen-lockfile
pnpm check
pnpm vendor:check
pnpm test:ci
```

Для Linux предварительно установите Chromium и его зависимости указанной выше командой Playwright. В Windows тесты по умолчанию используют Edge; каналы можно переопределить переменными PLAYWRIGHT_CHANNEL и EXTENSION_TEST_CHANNEL.

Локальная проверка Windows не подтверждает выполнение Ubuntu-runner или применение настроек GitHub. Для первого удалённого прогона требуется опубликовать workflow, package.json, pnpm-lock.yaml, скрипты, тесты и локальные vendor-файлы вместе.

Источники: [GitHub: безопасное использование Actions](https://docs.github.com/en/actions/reference/security/secure-use), [настройки Dependabot](https://docs.github.com/en/code-security/reference/supply-chain-security/dependabot-options-reference), [Playwright: CI](https://playwright.dev/docs/ci), [проверка расширений](https://playwright.dev/docs/chrome-extensions).
