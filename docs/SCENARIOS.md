# Пользовательские сценарии

Сценарий выполняется в отдельной вкладке только после явного разрешения в popup. Он предназначен для тестовых сайтов и тестовых данных. Клики, Enter и ввод могут вызвать сетевые запросы и изменить серверные данные; расширение не отменяет эти изменения. Не используйте реальные пароли, платёжные или персональные данные.

## Формат

```json
{
  "origin": "http://127.0.0.1:8080",
  "steps": [
    { "action": "fill", "selector": "#email", "value": "test@example.test" },
    { "action": "click", "selector": "#next" },
    { "action": "fill", "selector": "#password", "value": "test-password" },
    { "action": "paste-probe", "selector": "#password" },
    { "action": "checkbox", "selector": "#consent", "checked": true },
    { "action": "select", "selector": "#account", "value": "test" },
    { "action": "click", "selector": "#signin", "expect": { "selector": "#status", "text": "Вход выполнен", "visible": true } }
  ]
}
```

URL должен открывать ваш разрешённый тестовый сайт с соответствующими элементами. `origin` должен точно совпадать с протоколом, адресом и портом проверяемого URL, без пути и завершающего слеша. Разрешено не более 30 шагов. Произвольный JavaScript из сценария не выполняется.

| Действие | Поля | Поведение |
| --- | --- | --- |
| `fill` | `selector`, `value` | Только textarea и input типов text/search/email/password/tel/url; проверяет фокус и фактическое значение после ввода, поддерживает очистку пустой строкой |
| `checkbox` | `selector`, `checked` | Нативный input checkbox или role checkbox/switch; доверенный клик только при необходимости и ожидание состояния; indeterminate/mixed не поддерживаются |
| `radio` | `selector` | Нативный input radio или role radio; выбор элемента и подтверждение checked/aria-checked |
| `select` | `selector`, `value` | Нативный одиночный select, включая size > 1; клавиатурное управление и проверка значения; до 100 вариантов, disabled/hidden и неоднозначность отклоняются |
| `multiple` | `selector`, `values` | Нативный select multiple; Home/стрелки/Space с модификатором сохранения выбора и проверка полного набора; пустой массив снимает выбор |
| `listbox` | `selector`, `options` | ARIA-listbox и массив селекторов желаемых role option; доверенные клики и подтверждение набора aria-selected/aria-checked; до 100 вариантов |
| `aria` | `selector`, `state`, `value` | Доверенный клик и ожидание логического checked/selected/expanded/pressed; без присваивания ARIA через JavaScript |
| `pattern` | `selector`, `pattern`, `keys`, необязательный `focus`, обязательный `expect` при клавишах | Снимок структуры одного из 30 APG-паттернов и явно заданные клавиши; промежуточные и итоговые состояния подтверждаются, атрибуты не присваиваются |
| `click` | `selector` | Проверка попадания в центр цели или её потомка, наведение, повторная проверка, нажатие и отпускание; перекрытая, disabled/inert или переместившаяся цель отклоняется до нажатия |
| `key` | `key` | Tab, Escape, Enter, Space или одна из четырёх стрелок; без чтения буфера обмена |
| `drag` | `selector`, `target`, необязательные `mode`, `scroll`, `autoScroll` | Указательная последовательность или native; scroll true прокручивает к цели, autoScroll true включает краевой цикл с повторным измерением |
| `wait` | `ms` | Ожидание от 0 до 2000 мс |
| `observe` | `ms` | Наблюдение поздних статусов и медиа от 0 до 5000 мс, с опросом до 100 мс; не запускает действия сайта |
| `media` | `selector` | Снимок указанного пользовательского плеера, его HTMLMediaElement и элементов управления, включая открытые shadow-root; не запускает воспроизведение |
| `web-audio` | без дополнительных полей | Включает наблюдение Web Audio через debugger до конца workflow; контексты, граф, события и часы, без запуска или записи звука |
| `check` | необязательные `selector`, `expectedText` или `expect` | Ждёт совпадения текста после trim или условий expect; неоднозначный селектор сразу завершает проверку без passed; без условий только собирает наблюдения |
| `paste-probe` | `selector` | Синтетическое отменяемое событие paste с тестовой строкой; реальная системная вставка не выполняется |

Селектор действия должен находить один видимый элемент. Обычный CSS применяется к основному документу; `#host >>> #field` явно входит в открытый Shadow DOM, `#frame >>frame>> #field` — в iframe того же origin. Переходы можно сочетать. Закрытые shadow-root, чужой/непрозрачный origin, sandbox без allow-same-origin и iframe с CSS transform/zoom у него или предков отклоняются. Вход регистрирует наблюдателей контекста; максимум 20 контекстов. Произвольный обход всех фреймов не выполняется.

Примеры дополнительных шагов:

```json
[
  { "action": "radio", "selector": "#delivery" },
  { "action": "multiple", "selector": "#topics", "values": ["a", "b"] },
  { "action": "listbox", "selector": "#cities", "options": ["#city-two"] },
  { "action": "aria", "selector": "#details", "state": "expanded", "value": true },
  { "action": "fill", "selector": "#host >>> #email", "value": "test@example.test" },
  { "action": "fill", "selector": "#frame >>frame>> #field", "value": "Тест" },
  { "action": "drag", "selector": "#source", "target": "#drop", "mode": "native", "scroll": true },
  { "action": "media", "selector": "#player" },
  { "action": "observe", "ms": 1500 }
]
```

listbox/aria проверяют состояния после кликов, а не всю клавиатурную модель компонента. Для сложных случаев добавлен pattern с явно заданными клавишами и постусловиями. Клик-модель listbox по-прежнему не обслуживает виртуализованные списки, внешние aria-owns, смешанные состояния и скрытые изменяемые варианты; их поведение можно исследовать отдельным разрешённым клавиатурным сценарием, но полнота автоматически не подтверждается.

## Каталог ARIA-паттернов

pattern содержит все 30 записей текущего каталога APG: accordion, alert, alertdialog, breadcrumb, button, carousel, checkbox, combobox, dialog, disclosure, feed, grid, landmarks, link, listbox, menu-menubar, menu-button, meter, radio-group, slider, slider-multithumb, spinbutton, switch, table, tabs, toolbar, tooltip, tree-view, treegrid, window-splitter. Это имена сценарного интерфейса; они не являются дополнительными ролями ARIA.

Для всех записей доступно распознавание явно указанной структуры и снимок элементов/ARIA-атрибутов до и после шага. Пустой keys означает только наблюдение, без passed по паттерну. Совпадение role или тега само по себе не подтверждает правильность компонента. Проверки имён и семантики стандартного DOM-набора выполняются отдельно.

Пример реального клавиатурного сценария:

```json
{
  "action": "pattern",
  "pattern": "slider",
  "selector": "#volume",
  "keys": [
    { "key": "ArrowRight", "expect": { "selector": "#volume", "attributes": { "aria-valuenow": "2" } } },
    { "key": "Home" }
  ],
  "expect": { "selector": "#volume", "attributes": { "aria-valuenow": "0" } }
}
```

До 30 клавиш на шаг. Поддерживаются стрелки, Tab, Escape, Enter, Space, Home, End, PageUp/PageDown, Backspace/Delete, F2/F10, одна буква или цифра для typeahead, включая русские буквы. modifiers использует флаги CDP: Alt 1, Control 2, Meta 4, Shift 8. Печатные сочетания ограничены обычным вводом, Shift и Control+A; переключение вкладок через Control+Tab не разрешается. Произвольные браузерные команды и JavaScript не выполняются.

focus задаёт начальный элемент внутри контейнера, например tab внутри tablist. Без focus интерактивный шаг пытается сфокусировать selector. Перед каждой следующей клавишей проверяется фокус в контейнере или явно связанном aria-controls/aria-owns компоненте. При выходе фокуса следующие нажатия прекращаются. Каждая клавиша может иметь собственный expect; итоговый expect обязателен при непустом keys. Отпускание клавиши проверяет origin/документ, но допускает штатное изменение фокуса. Закрытие/удаление диалога допускается на последней клавише только при итоговом visible false для исходного selector; замена другим узлом не допускается.

Это общий исполнитель заданных сценариев для каталога, а не 30 полных автоматических аудитов. Все необязательные комбинации, screen-reader-взаимодействия, виртуализация, семантика и альтернативные реализации автоматически не покрываются. Отдельно проверены распознавание всех 30 записей, реальные клавиши slider/spinbutton/tabs/combobox/tree/dialog, связанный popup, русскоязычный typeahead и прекращение ввода при потере фокуса. Переход документа внутри клавиатурного шага сохраняет прежний запрет; для навигации есть отдельные click/check.

Модель видимости учитывает геометрию, display, visibility и нулевую opacity элемента и предков, а также content-visibility: hidden. Частичная прозрачность допускается; это не пиксельная проверка читаемости, цвета текста, масок и всех способов обрезания. Проверка попадания click выполняется перед нажатием, но не гарантирует неизменность страницы во время обработки событий. Прикладной результат подтверждается expect или отдельным check.

Текстовые условия сравнивают отображаемые текстовые узлы, исключая скрытых/прозрачных потомков и служебное содержимое script/style/template/noscript. Условия сохраняют trim без добавления переносов между блоками; CSS-преобразование текста, все способы обрезания и generated content этим не воспроизводятся. Исходный HTML проблемного элемента не фильтруется и не переводится.

Перед каждой командой Input проверяются origin, документ и привязка к исходному DOM-узлу. Замена узла другим с тем же селектором, исчезновение цели, потеря фокуса ввода и изменение вариантов select прерывают действие без completed. Проверяются порядок и идентичность option, value, подпись и доступность, включая optgroup. Это не атомарная блокировка: сайт может измениться между проверкой и браузерным событием.

Ввод во фрейме разрешён только при явном >>frame>> в селекторе; случайное попадание в iframe/object/embed через контейнер отклоняется. Обычный переход после завершённого действия допускается в пределах origin. Перетаскивание внутри iframe и между документами не поддерживается.

На время workflow debugger перехватывает Document-запросы через Fetch. Переходы на чужой origin, включая редиректы и перехваченные запросы документов фреймов, отклоняются до отправки; подресурсы не блокируются этим правилом. При прерывании незавершённая загрузка останавливается, затем отключается Fetch, удаляются слушатели и отсоединяется debugger. Это не изоляция всех сетевых действий сайта; отдельные OOPIF-сессии не подключаются.

## Постусловия действий

У любого шага может быть expect с однозначным selector и хотя бы одним условием: text, value, values, checked, selected, expanded, pressed, visible, enabled, focused или attributes. Последний объект сравнивает до 20 aria-* атрибутов со строкой либо null для отсутствия; атрибуты без префикса aria- и обработчики событий отклоняются. Проверка атрибута не подтверждает корректность его имени/значения по спецификации. При явном visible false можно читать атрибуты существующего скрытого элемента. Условия ожидаются совместно до timeoutMs. Пример: `{ "action": "click", "selector": "#next", "expect": { "selector": "#email", "enabled": true, "focused": true } }`.

Для текста, значений и состояний нужна видимая цель; value относится к нативным input/textarea/select, checked — к checkbox/radio без indeterminate или aria-checked. selected/expanded/pressed проверяют соответствующие ARIA-атрибуты; отсутствие и mixed не считаются false. enabled учитывает disabled, aria-disabled и inert. Только visible false допускает отсутствующую цель. Неверные типы и неизвестные ключи отклоняются до подключения debugger.

При тайм-ауте постусловия шаг не попадает в completed, а проверка не получает passed. При успехе в checks сохраняются только имена условий, без ожидаемых значений. steps[].confirmation различает postcondition, expected-text, control-state, observation-only и dispatch-only; клик или клавиша без expect не подтверждают прикладной результат. Постусловие фиксирует состояние, а не доказывает его причину или устойчивость в будущем.

Для проверки текста и принятого ввода можно задать `timeoutMs`: целое число от 0 до 5000, по умолчанию 2000 мс. При 0 условие проверяется сразу. Например: `{ "action": "check", "selector": "#status", "expectedText": "Готово", "timeoutMs": 4000 }`. Неоднозначность селектора и неподдерживаемый тип поля не маскируются ожиданием.

Обычные шаги больше не используют безусловную паузу 150 мс: проверяется готовность документа и короткий период без наблюдаемых DOM-изменений, а для `check`/`fill` ожидается конкретный результат. После навигации ожидается новый модуль; при смене origin сценарий останавливается. Стабилизация DOM не гарантирует завершения всех будущих таймеров и запросов приложения: для значимого результата задавайте явный `check`. `wait` остаётся явно запрошенной пользователем задержкой.

Без scroll true или autoScroll true источник и цель drag должны помещаться в один viewport. scroll true выполняет scrollIntoView после захвата. autoScroll true включает краевой цикл: поиск видимой области, движение к её краю, ожидание автопрокрутки приложения/браузера и wheel при недостаточном продвижении. Поддерживаются документ и вложенные области overflow auto/scroll, обе оси и RTL. Координаты цели вычисляются заново; идентичность обоих узлов проверяется между командами.

Если wheel не продвигает область либо перехваченный native drag прокручивается медленно, выполняется небольшой резервный scrollBy актуального контейнера. Он не заменяется мгновенным переходом к цели; assistedScrolls отражает число таких шагов. Поэтому успешное достижение цели не доказывает, что сам сайт реализует краевую автопрокрутку без помощи расширения. Не более 100 итераций и timeoutMs шага, с учётом общего бюджета; достижение лимита даёт incomplete и запрещает следующие действия. Счётчики, время и завершённость сохраняются в dragObservations и человекочитаемых отчётах.

Временно недоступный край проверяется повторно в том же бюджете времени и итераций, без отправки указательных событий через перекрытие. Постоянное перекрытие не даёт completed: по достижении лимита сохраняется причина недоступности. Замена или исчезновение цели прерывают действие без ожидания; перед резервной прокруткой геометрия проверяется заново, и при изменившейся области или уже достигнутой цели wheel по прежним координатам не отправляется.

Native-режим ждёт реальное dragIntercepted до timeoutMs, использует данные сайта, запрещает файлы и более 100 элементов данных. После него отменяется незавершённый drag и отключается перехват. Ошибка экспериментальных команд CDP даёт неполный результат. Прикладной эффект подтверждается expect. Универсальность для произвольных canvas, закрытых компонентов, любых CSS-преобразований, нестандартной физики и iframe не заявляется; при недоступной области цикл прекращается без фиктивного успеха.

Нативные списки управляются клавиатурой, а не присваиванием value и синтетическими событиями; изменение состава/доступности вариантов не вызывает автоматический повтор действия. Radio выбирает конкретную кнопку; отдельного снятия radio или действия для числовых полей нет.

## Что собирается

- После действий проверяются изменения статусных сообщений и связи описаний ошибок у `aria-invalid="true"`.
- Для статусов сохраняется снимок текста и видимости. Учитываются изменение непустого видимого текста и появление сообщения, в том числе при изменении видимости предка; изменение только цвета или класса без изменения текста и видимости не учитывается. Наблюдение не подтверждает фактическую речь скринридера и может пропустить промежуточные состояния между чтениями. Для сообщений в изменённых поддеревьях действует отдельный лимит 200 кандидатов с записью усечения в coverage.
- Снимок статуса использует тот же renderedText, что check/expect. Изменения скрытых потомков и служебных script/style не считаются изменением сообщения; их появление учитывается. Исходный outerHTML не фильтруется, в том числе для смешанного видимого и скрытого содержимого.
- Поля сопоставляются по нормализованным токенам autocomplete: учитываются section-*, shipping/billing и home/work/mobile/fax/pager, регистр ASCII и пробельные разделители HTML. Неверные токены, off/on, парольные назначения, one-time-code и cc-csc не сравниваются. Значения полей не сохраняются: только факт заполнения и ссылка на исходный шаг/селектор.
- Для полей без атрибута autocomplete сопоставляются точные подписи label/aria-label/aria-labelledby после нормализации Unicode, регистра и пробелов, отдельно по форме, контексту и типу поля. ID/name не используются для угадывания смысла; явно заданные off/on и неверные токены не обходятся этим механизмом. Пароли и исключённые чувствительные типы не сравниваются.
- Кандидат 3.3.7 — обязательное пустое поле с тем же назначением и областью, которое появилось, стало обязательным, было очищено либо уже присутствует при первом обнаружении заполненного аналога. Необязательные, disabled, readonly и скрытые поля не выдаются за повторный запрос. Точное совпадение подписи остаётся эвристикой; смысл, разные обозначения одной информации, выбор ранее введённых данных и исключения требуют ручной оценки.
- Отмена пробного paste — кандидат на ручную проверку 3.3.8. Нельзя выводить соответствие при отсутствии отмены: обработчик может иначе реагировать на доверенную вставку, а аутентификация включает и другие требования.
- Перетаскивание и альтернативный клик можно выполнить по очереди с проверкой ожидаемого текста. Смысловая эквивалентность действий остаётся ручной оценкой.
- При переходе на другой origin сценарий останавливается перед следующим действием. Длительная загрузка или отсутствие внедрённого модуля приводит к явному неполному результату, а не к успешному тесту.

В `coverage.workflow` записываются номера и типы выполненных шагов, переходы между документами, статус выполнения и ограничения. Успешные сравнения ожидаемого текста сохраняются отдельно как конкретные технические тесты `checks` со статусом `passed`; это не вердикт о соответствии критерию. `debugger.attached` отражает фактическое подключение, `debugger.detached` — подтверждённое завершение соединения, в том числе внешнее. Значения ввода в журнал шагов не включаются. При этом отчёты содержат HTML проблемных элементов и текст сообщений сайта; сам сайт может отобразить введённые данные. Это ещё одна причина использовать только тестовые данные.

При потере debugger пользовательский сценарий получает incomplete; оставшиеся действия не отправляются, автоматического повторного подключения нет. Сохраняются connectionLost и detachReason: target_closed для закрытой вкладки, canceled_by_user при соответствующем onDetach или not_attached при подтверждённом отсутствии собственной сессии без события. В человекочитаемых отчётах причина объясняется по-русски. Признак getTargets().attached не подтверждает владение сессией: к той же вкладке может быть подключён другой отладчик, поэтому перед обычной инспекцией и после её ответа выполняется безопасная проверка Page.getFrameTree через собственный транспорт.

Результат ожидания, полученный уже после потери сессии, не записывается как passed. При живой вкладке расширение пытается остановить своих DOM-наблюдателей через scripting; при закрытии вкладки её контекст уничтожается. Слушатели debugger удаляются в обоих случаях. Уже потерянная сессия повторно не отсоединяется, чужое подключение не затрагивается. Если во время потери соединения уже выполнялась инспекция страницы, ожидание ограничено её существующим тайм-аутом, а не обязательно прерывается мгновенно.

Для select дополнительно проверены отмена клавиатурного действия через preventDefault и возврат прежнего значения обработчиком change. Неподтверждённое значение завершает сценарий без completed и passed и без следующих действий; лишний Escape в документ не отправляется. Это не утверждение о поведении Escape во всех вариантах нативного меню браузера.

Бюджет времени 30 секунд контролируется между шагами и перед Input; это не принудительный тайм-аут каждой браузерной команды. После завершения наблюдатели отключаются и debugger отсоединяется. Закрытие popup не отменяет разрешённую фоновую проверку: она завершает работу и очистку, но закрытое окно не получает ответ. Сквозной тест проверяет отсутствие оставшейся вкладки и слушателей. Изменения сайта не откатываются.

observe сохраняет coverage.workflow.statusObservations: документ, длительность, время изменения, отображаемый текст и полный HTML. Лимит 200 сохранённых изменений отражается в охвате. Периодический опрос CSS-видимости включается только в observe. Промежуточные состояния между чтениями могут быть пропущены.

## Наблюдение медиа

Во время пользовательского и автоматического сценария регистрируются доверенные события play, playing, pause, ended, volumechange, timeupdate, waiting, stalled, emptied, loadstart, error и ratechange. Синтетический dispatchEvent не считается воспроизведением. Наблюдение не запускает плеер самостоятельно; новые медиаэлементы регистрируются при вставке в документ.

Интервал потенциально звукового воспроизведения ограничивается и временем наблюдения, и продвижением currentTime с учётом playbackRate. Пауза, ожидание данных, muted, нулевая громкость и смена источника разделяют интервалы; длина файла сама по себе не подтверждает три секунды воспроизведения. Наблюдаемый интервал более 3000 мс создаёт только кандидат для ручной проверки 1.4.2. DOM не доказывает наличие звуковой дорожки, слышимость, причину запуска и доступность пользовательского механизма остановки.

Для короткого loop допускается объединение наблюдаемой границы цикла: возврат к началу от последних 0,5 × playbackRate секунд ресурса, позиция до 0,25 секунды и возобновление playing не позднее 250 мс. Количество таких границ сохраняется в loops. Пауза, muted, смена источника и обычная перемотка не объединяются. Это эвристика потенциального воспроизведения: ручная перемотка у самой границы может быть неоднозначна, а слышимость короткого разрыва автоматически не оценивается. Сетевой stalled сам по себе не считается остановкой продвижения currentTime.

В `coverage.workflow.mediaObservations` сохраняются отдельные документы; в `coverage.scenarios.mediaObservation` — наблюдение автоматического режима. Записываются длительность, до 100 элементов и до 200 событий, longestPotentialAudioMs, playObserved, activationAtPlay, autoplayAttribute и playingAtStart (состояние при регистрации элемента). Эти признаки не являются выводом об автозапуске. Промежутки загрузки документов и события до начала наблюдения не восстанавливаются; после завершения слушатели удаляются, снимок наблюдения больше не растёт. Основной DOM-аудит без сценария сохраняет только структурные медиапроверки.

## Пользовательские плееры

Действие media сохраняет coverage.workflow.playerObservations: контейнер плеера, найденные HTMLMediaElement и элементы управления. Поддерживается явно выбранный контейнер в разрешённом фрейме и вложенные открытые shadow-root; вложенные iframe автоматически не обходятся. Это инвентаризация, а не доказательство связи каждого контрола с медиа. Web Audio наблюдается отдельным действием, без чтения звука. На media действуют лимиты 20 контекстов, 100 медиаэлементов и 100 контролов.

## Web Audio

web-audio включает экспериментальный домен CDP WebAudio в текущей debugger-сессии. API страницы не переопределяются; обработчик не читает микрофон, не записывает отсчёты и не запускает контексты самостоятельно. Важно включить наблюдение до действия, создающего/запускающего граф. Данные событий до включения не гарантируются; отдельные OOPIF/worker-сессии не подключаются. Контексты root-сессии не сопоставляются с конкретным DOM-плеером или origin фрейма.

```json
[
  { "action": "web-audio" },
  { "action": "click", "selector": "#play" },
  { "action": "observe", "ms": 1500 },
  { "action": "click", "selector": "#stop" }
]
```

coverage.workflow.webAudioObservation содержит тип/состояние контекстов, sampleRate, узлы и соединения, ограниченный журнал событий и измерения currentTime. longestRunningMs ограничен одновременно прошедшим временем и продвижением часов; смена состояния сбрасывает текущий интервал. Это время работы контекста, не потенциально слышимое воспроизведение: граф с нулевым GainNode тоже может продвигать часы. По этому показателю не создаётся нарушение 1.4.2. Смысл, громкость, автоматический запуск и доступность управления требуют отдельного подтверждения.

Лимиты: 20 контекстов, 200 узлов, 200 событий соединения графа, 300 сохранённых событий и 100 измерений на контекст. Усечение сохраняется в coverage.limits; ошибки включения/измерения и очистки делают результат неполным. Окончание workflow отключает домен перед отсоединением debugger; дальнейшие события не меняют сохранённое наблюдение. Сам AudioContext сайта не закрывается расширением: это допустимо только через явно заданное действие сайта.

## Лимиты и полнота охвата

`coverage.limits`, `coverage.scenarios.limits` и `coverage.workflow.limits` содержат количественные ограничения соответствующих проходов. Запись включает `id`, русскую подпись `label`, `limit`, `total`, `processed` и `truncated`. Для повторных выборок сохраняются наибольшие размеры пакетов и факт любого усечения, а не сумма повторных проверок одних узлов. `processed` означает количество отобранных кандидатов или сохранённых замечаний, не число полностью проверенных критериев.

Когда полный размер неизвестен из-за ранней остановки, используется `totalIsLowerBound`: значение total читается как «не менее». В частности, наблюдатель сохраняет не более 200 узлов и сигнализирует переполнение при попытке добавить следующий. Ровно 200 узлов не считается усечением. Пропущенные записи наблюдателя учитываются отдельно; для них не утверждается точное число уникальных узлов.

Отражаются лимиты 200 наблюдаемых узлов и сообщений в изменённых поддеревьях, 200 медиасобытий, 100 наблюдаемых медиаэлементов и вариантов select, 10 подсказок, 100 медиаплееров и полей снимка, 1000 полей проверки ошибок, 2500 элементов сценарного снимка, замечаний геометрии, клавиатурных шагов, бюджета времени и количественные ограничения старого сканера. Лимит, достигнутый до продолжения прохода, делает соответствующий охват неполным даже при успешных выполненных шагах. Валидационные ограничения JSON, длины строк и ожиданий отклоняют недопустимый сценарий, а не создают нарушение WCAG.

Человекочитаемые отчёты показывают усечённые выборки и неполный охват даже без найденных проблем. Полные записи ограничений сохраняются в JSON. Старые эвристики по-прежнему ограничены viewport; счётчики выборок не превращают их в аудит всей страницы.

## Автоматические сценарии без JSON

Флажок «Сценарная проверка фокуса и адаптации» включает reflow, увеличение шрифта, Tab/Shift+Tab, наблюдение статусов и ограниченный поиск связанных подсказок. Для подсказок используются `aria-describedby`/`aria-controls` и `role="tooltip"`, реальные движения указателя, фокус и Escape. Контрольный viewport и layout ожидаются по состоянию, а появление и закрытие подсказки наблюдаются до 1000 мс. Неожиданное состояние по тайм-ауту фиксируется в `coverage.scenarios.timeouts` и делает охват неполным. Несвязанные и появляющиеся позже подсказки могут быть пропущены; отсутствие закрытия по Escape не доказывает нарушение, поскольку есть исключения и альтернативные способы закрытия.

Медиапроверки выполняются и без JSON: автоматически обнаруживается отсутствие нативных controls или встроенных track, а при включённом сценарном режиме наблюдаются события воспроизведения. Применимость критерия и наличие пользовательских альтернатив подтверждаются вручную. Напоминания только по наличию `autocomplete="off"` или `draggable="true"` исключены. Аутентификация и перетаскивание исследуются только конкретными шагами разрешённого сценария. Расширение не проверяет качество субтитров, все пользовательские плееры, CAPTCHA, поддержку конкретного менеджера паролей и фактические объявления скринридером; для них не создаются фиктивные результаты проверки.

Автоматически подтверждённые нарушения отмечаются `assessment: automatic`, наблюдения для ручного подтверждения — `assisted`. Невозможность измерить сложный фон — `not-tested` в охвате, а не обнаруженная проблема. Диагностика подключения и выполнения сценария не является проверкой требования WCAG.

## Проверка расширения

`pnpm test` включает загрузку распакованного расширения в отдельный временный профиль браузера. Тест проверяет настоящее разрешение debugger, сценарный аудит, локальную имитацию входа, ошибку формы, изменение статуса, перетаскивание с альтернативным действием, переход на следующую страницу, конфликт отладчика и закрытие вкладок.

Дополнительно проверяются checkbox/select и постусловия в настоящем расширении, реальные медиасобытия локального WAV в отдельном контексте, отменённые изменения, ошибки схемы до подключения debugger, лимиты и сведения в HTML/Markdown/текстовых отчётах.

Регрессии безопасности включают замену документа между командами ввода и отклонение прямого перехода/редиректа на другой локальный origin настоящим расширением; проверяются отсутствие запросов к чужому серверу и очистка слушателя debugger. Дополнительно проверены скрытый текст потомков, короткий loop и фактическая перемотка seekable WAV.

Новые сквозные сценарии отключают debugger и закрывают вкладку после подтверждённого начала ожидания. После отключения ожидаемый текст специально появляется: это не должно создавать passed или запускать следующий fill. Проверяется остановка DOM-наблюдения в оставшейся вкладке и отсутствие слушателей onEvent/onDetach. Отдельный сценарий настоящего расширения проверяет восстановление прежнего значения select сайтом. Модельные тесты дополнительно проверяют событие отключения и потерю без onDetach при наличии другого отладчика.

В Windows используется Edge; канал сквозного теста можно переопределить через `EXTENSION_TEST_CHANNEL`. На других системах используется Chromium из Playwright, который нужно установить командой `pnpm exec playwright install chromium`. Личный профиль пользователя и существующий CRX не используются.

Минимальная версия движка — Chromium 118: начиная с неё активная сессия debugger поддерживает жизнь service worker. Источник: [жизненный цикл service worker расширения](https://developer.chrome.com/docs/extensions/develop/concepts/service-workers/lifecycle#chrome-118).

События завершения сессии сверяются с [chrome.debugger.onDetach](https://developer.chrome.com/docs/extensions/reference/api/debugger#event-onDetach); not_attached — внутреннее обозначение подтверждённого отсутствия нашей сессии, а не дополнительное значение enum Chrome.

Модель listbox сверяется с [WAI-ARIA APG: Listbox Pattern](https://www.w3.org/WAI/ARIA/apg/patterns/listbox/): фокус и выбранность различаются, а модели множественного выбора неодинаковы. Поэтому действие подтверждает выбранность после явно заданных кликов, не объявляя весь паттерн проверенным. Нативный Drag and Drop использует setInterceptDrags, dragIntercepted и dispatchDragEvent из [официальной схемы CDP](https://github.com/ChromeDevTools/devtools-protocol/blob/master/json/browser_protocol.json); это экспериментальные возможности браузера.

При интерпретации наблюдений используются [WCAG 1.4.13](https://www.w3.org/WAI/WCAG22/Understanding/content-on-hover-or-focus.html), [4.1.3](https://www.w3.org/WAI/WCAG22/Understanding/status-messages.html), [2.5.7](https://www.w3.org/WAI/WCAG22/Understanding/dragging-movements.html), [3.3.7](https://www.w3.org/WAI/WCAG22/Understanding/redundant-entry.html) и [3.3.8](https://www.w3.org/WAI/WCAG22/Understanding/accessible-authentication-minimum.html).

Разбор autocomplete опирается на [HTML Standard: autofill](https://html.spec.whatwg.org/dev/form-control-infrastructure.html#autofill), нативный выбор — на [HTML Standard: select](https://html.spec.whatwg.org/multipage/form-elements.html#the-select-element). Наблюдение звука отделено от вывода об автозапуске и механизме остановки согласно [WCAG 1.4.2](https://www.w3.org/WAI/WCAG22/Understanding/audio-control.html).
